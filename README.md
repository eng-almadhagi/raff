## تشغيل المسار السابق وأدوات الاستيراد

المطلوب Python 3.11 أو أحدث. لا تحتاج تجربة التطبيق أو الاختبارات إلى حزم خارجية.

```sh
python -m raf.cli init
python -m raf.server
```

افتح http://127.0.0.1:8000. على Windows يمكن استخدام `py` بدل `python`. نفّذ الأوامر من جذر المشروع. الخادم المحلي للتطوير؛ للإنتاج استخدم Waitress أو Docker أدناه.

```sh
python -m unittest discover -v
python -m tools.package --check
python -m tools.package
```

ينشئ الأمر الأخير `dist/raf-github-ready.zip` بقائمة ملفات عامة محددة. لا ترفع المجلد كاملًا بالسحب إلى GitHub؛ استخدم الحزمة أو Git مع مراجعة `.gitignore`. نصوص المصادر والفهارس وقواعد البيانات وملفات الأسرار مستبعدة.

## تجربة الكتاب الخاص محليًا

البيانات غير مرفقة بحزمة GitHub. على جهاز العمل الحالي النسخة محفوظة في `private/fatawa1708` والنموذج في `var/models/multilingual-e5-small`.

```powershell
.\.venv\Scripts\python.exe -m tools.check_full_book
.\.venv\Scripts\python.exe -m tools.import_local
.\.venv\Scripts\python.exe -m raf.local
```

يفتح الخادم الخاص على http://127.0.0.1:8000 فقط. يجب إيقاف أي خادم قديم يستخدم المنفذ أولًا. يخزن النص والفهرس في `var/local-research.sqlite3`، ويعيد استخدام embeddings المحفوظة عند استكمال عملية انقطعت. لا يجلب نصوصًا وقت البحث ولا يستخدم API مدفوعًا. لا تستخدم `raf.local` للنشر؛ لا يُعد هذا المسار موافقة حقوق أو مراجعة علمية. للنشر لاحقًا استخدم مسار الإنتاج بعد اعتماد إصدار جديد؛ راجع [النشر](docs/deployment.md).

## إضافة كتاب أو تحديثه

1. أنشئ ملف JSON خاصًا وفق [عقد البيانات](docs/data-contract.md). اختر `book_id` ثابتًا ونطاقًا واضحًا. الإصدار الجديد يأخذ `release_id` جديدًا.
2. ضع قائمة صفحات النطاق، النصوص الأصلية، الحواشي المرتبطة، البصمات والمراجعات في ملف خاص خارج المستودع العام.
3. جهّز 40 سؤال تقييم مستقلًا على الأقل بمراجع صحيحة. لا تعتبر بيانات الاختبار الاصطناعية دليلًا على جودة المنتج الفقهي.
4. شغّل المسار نفسه لكل كتاب:

```sh
python -m raf.cli import private/book.json
python -m raf.cli evaluate fatawa-islamiyyah-1708 v1 private/heldout.json
python -m raf.cli publish fatawa-islamiyyah-1708 v1 --reviewer "اسم المراجع المسؤول"
python -m raf.cli books
```

الاستيراد والفهرسة لا ينشران المحتوى. التفعيل يفشل دون اجتياز التقييم وتوثيق إذن العرض والمراجعة العلمية. يبقى الإصدار السابق متاحًا أثناء تجهيز الجديد. يمكن الرجوع إلى إصدار ناجح سابق بالأمر `publish` نفسه. لا توجد واجهة إدارة عامة؛ الإدارة عبر الجهاز/الخادم الموثوق فقط.

كل عمليات البحث تقيَّد بالكتاب وإصداره النشط، حتى عند تطابق معرف الوحدة بين كتابين. تغيّر نطاق كتاب موجود يستلزم معرّف كتاب جديدًا.

## البحث بالمعنى

### تشغيل محلي دون مفتاح API

```sh
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
python -m pip install -r requirements.txt -r requirements-semantic.txt
python -m tools.setup_model
```

أمر setup_model ينزّل نحو 136 MB من ملفات ONNX/tokenizer إلى `var/models/` مرة واحدة. لا يحدث أي تنزيل عند بدء الخادم. في PowerShell:

```powershell
$env:RAF_EMBED_BACKEND = 'local'
python -m tools.benchmark
$env:RAF_RUN_MODEL_TESTS = '1'
python -m unittest discover -v
python -m raf.production
```

وفي Linux/macOS استخدم `export RAF_EMBED_BACKEND=local`. تنزيل النموذج لا ينشر أي كتاب؛ يجب استيراد البيانات المسموح بها وتقييم الإصدار وتفعيله بالمسار نفسه. الأسئلة تبقى محلية عند استخدام هذا الخيار.

### خدمة Ollama موجودة مسبقًا

البحث الافتراضي BM25 بالكلمات. كخيار بديل للمحلي يوجد تكامل اختياري مع `/api/embed` في Ollama. يلزم نموذج يدعم العربية، والتحقق من رخصته، وتشغيله بصورة مستقلة. لا يُنزّل المشروع أي نموذج تلقائيًا.

عيّن `RAF_EMBED_URL` و`RAF_EMBED_MODEL` في بيئة الخادم، ثم استورد إصدارًا جديدًا وأعد تقييمه. يقارن التقييم الكلمات والمعنى والهجين على الأسئلة نفسها. فشل المزود أو اختلاف النموذج يؤدي إلى خطأ واضح؛ لا يتحول سرًا إلى بحث بالكلمات.

اختر `RAF_EMBED_BACKEND=ollama` إذا كنت قد فعّلت المحلي سابقًا. يُحفظ النمط المختار في manifest.retrieval.mode؛ لا تفترض تفوق الهجين دون قياس.

ملف `.env.example` توثيق للإعدادات؛ التطبيق لا يقرأ `.env` تلقائيًا. مثال PowerShell:

```powershell
$env:RAF_EMBED_URL = 'http://127.0.0.1:11434'
$env:RAF_EMBED_MODEL = 'اسم-النموذج-المثبت'
python -m raf.cli import private/book.json
```

هذه النسخة تستخرج النصوص المطابقة وتتحقق من الاقتباس؛ لا تولّد شرحًا فقهيًا جديدًا. المصنف احترازي قائم على قواعد، وليس فهمًا دلاليًا مكتملًا للحالات الشخصية. راجع [الحدود والسياسة](docs/policy.md).

## GitHub والتشغيل على خادم

الحزمة جاهزة للرفع إلى مستودع؛ لم تُرفع إلى حساب ولم يُنشأ رابط عام. GitHub يستضيف الكود ويشغّل CI؛ **GitHub Pages لا يشغّل خادم Python أو SQLite**.

```sh
python -m pip install -r requirements.txt
python -m raf.production
```

أو:

```sh
docker compose up --build -d
```

استخدم خادمًا يدعم Docker أو Python مع قرص دائم لـ `RAF_DB` وTLS أمام الخدمة. الإعداد المحلي للحاوية يربط المنفذ بـ127.0.0.1. تفاصيل الشبكة والنسخ الاحتياطي في [النشر](docs/deployment.md). قاعدة البيانات لا تدخل صورة الحاوية ولا مستودع GitHub. لا توجد حسابات مستخدمين أو تخزين محادثات على الخادم.
