# عقد إضافة الكتب

ملف الاستيراد كائن JSON يحوي `manifest` و`units`. جميع الكتابات تتم في معاملة واحدة؛ أي خطأ يمنع حفظ الإصدار. الفهرسة تسبق المعاملة، ولذلك فشل مزود المعنى لا يترك إصدارًا جزئيًا.

## manifest

```json
{
  "book_id": "salah",
  "release_id": "v1",
  "title": "كتاب الصلاة",
  "scope": "وصف دقيق ثابت لحدود الكتاب",
  "source_name": "الموسوعة الفقهية للدرر السنية",
  "allowed_hosts": ["dorar.net"],
  "rights": {
    "publish_allowed": false,
    "evidence": "",
    "operations": {
      "index": false,
      "embeddings": false,
      "provider_processing": false,
      "display_full_units": false
    }
  },
  "scientific_review": {"approved": false, "reviewer": ""},
  "coverage": {
    "expected_page_ids": ["معرف صفحة من قائمة الحصر"],
    "complete": false,
    "structure_reviewed": false,
    "note": "تغطية جزئية؛ صف النواقص بوضوح"
  }
}
```

`book_id` و`release_id` ومعرفات الوحدات: حروف لاتينية صغيرة وأرقام وشرطة/شرطة سفلية، من 2 إلى 64 حرفًا، وتبدأ بحرف. المعرف العلمي الأصلي للصفحة محفوظ مستقلًا. لا تضع قيم true للمراجعة والحقوق قبل تحققها فعليًا.

## units

قبل الاستيراد يلزم دليل حقوق غير فارغ و`index: true`. توليد المتجهات يحتاج `embeddings: true`، وأي مزود HTTP (حتى المحلي) يحتاج `provider_processing: true`. نشر الإصدار وعرض الإجابات يحتاجان `display_full_units: true` و`publish_allowed: true` لأن العارض الحالي يعيد الوحدات وحواشيها كاملة. إذن المقتطفات وحده لا يكفي؛ لا يوجد قص تلقائي يثبت الامتثال. الإصدارات القديمة التي تحمل publish_allowed فقط تُرفض في العرض، وتحتاج إصدارًا جديدًا بعد مراجعة الإذن الحقيقي. انظر [مراجعة حقوق الدرر](dorar-rights-review.md).

لكل وحدة: `book_id`, `id`, `title`, `path` (مصفوفة عناوين)، `page_id`, `url` (HTTPS من مضيف مسموح)، `text` (نص أصلي دون تغيير)، `sha256`, `fetched_at` (ISO 8601)، `verification` (`reviewed` بعد الفحص)، `reviewer`, `footnotes`، `previous_id`, `next_id` (معرفات داخل الإصدار أو null).

بصمة النص تُحسب بالدالة `raf.text.digest(text)`؛ تستخدم تمثيل JSON قياسيًا بترميز UTF-8، وليست بصمة بايتات الملف الخام. بصمة الإصدار تشمل البيانات والمتجهات والنموذج. الحاشية كائن `{ "marker": "[1]", "text": "النص الأصلي للإحالة" }` ويجب وجود العلامة في نص الوحدة.

التقسيم على حدود المسائل يتم في تجهيز المصدر ومراجعته، وليس بقص كل عدد ثابت من الحروف. حد الوحدة 30 ألف حرف؛ راجع حدود سياق نموذج المتجهات. يحتفظ البحث بنص معالج منفصل، وتُعرض النسخة الأصلية مع الحواشي. لا يمكن للفحص البرمجي إثبات عدم سقوط استثناء أو نسبة قول؛ المراجعة العلمية لازمة.

## التقييم

ملف JSON لمصفوفة من 40 سؤالًا مختلفًا على الأقل:

```json
[
  {"question":"سؤال مراجع مستقل عن أمثلة التطوير", "expected_ids":["unit-id"], "split":"heldout"}
]
```

القائمة الفارغة في `expected_ids` تعني توقع عدم استرجاع نتيجة. معيار البوابة الحالي صارم: وصول إلى أحد المراجع الصحيحة ضمن أول 3 نتائج لكل حالة في النمط المختار للإصدار. بقية الأنماط للمقارنة ولا تمنع النشر لمجرد إخفاق معيار الكلمات. لا يمثل ذلك إثبات أن النص يجيب السؤال؛ سجل التقييم يقيس الوصول ومطابقة الاقتباس فقط. يجب توسيع البنك المراجع لقياس دعم الادعاءات والامتناع غير الضروري قبل الإطلاق العلمي.

يمكن إضافة `"retrieval":{"mode":"semantic"}` إلى manifest؛ القيم الأخرى lexical وhybrid. الدلالي والهجين يتطلبان نموذجًا أثناء الاستيراد. الإعداد محفوظ ضمن بصمة الإصدار. الافتراضي hybrid عندما يوجد نموذج وlexical خلاف ذلك؛ يجب اختيار النمط بناء على تقييم مستقل للكتاب، لا على بنك الاختبار التقني الصغير.

يمكن حفظ الحاشية بمواضع Unicode `start` و`end` بدل marker. يجب أن يساوي `text[start:end]` نص الحاشية حرفيًا. يستخدم محلل HTML هذا الشكل كي لا يضيف أرقامًا مصطنعة إلى الاقتباس الأصلي.

## إدارة الإصدارات

لا يُعاد استعمال معرف إصدار موجود. لا تتغير النسخة المتاحة للمستخدم حتى `publish`. عملية النشر تغير مؤشرًا واحدًا في معاملة SQLite وتكتب أثرًا في `audit`. يسمح الرجوع لإصدار اجتاز بوابته. لا توجد كلمات مرور أو مفاتيح داخل الملفات. حزمة الكتاب وصلاحيات المراجع ومدخلات CLI حدود ثقة إدارية؛ لا تشغل الاستيراد على ملفات مجهولة دون مراجعة.


## امتداد فتاوى إسلامية 0.3

الكتاب الحالي `fatawa-islamiyyah-1708`، ومعرفا المصدر منفصلان: turath=1708 وalbahith=1472. `source_refs` يحفظ page_id وbahith_page_id وsequence_num وpart وpage_num (nullable). `question` و`answer` و`mufti` و`fatwa_number` بيانات من النص فقط؛ غير المتاح null. مرشح الاستيراد pending ولا يعتمد نفسه. `boundary_review_required: true` و`url_verification` غير verified يمنعان الاستيراد التشغيلي.

`retrieval.chunk_chars: 300` يفعّل فهرسة مقاطع ذات مواضع داخل النص الأصلي، مع إرجاع الوحدة كاملة بعد الاسترجاع. المقاطع في جدول chunks، والمتجهات المعاد استخدامها في embedding_cache بمعرف الكتاب والنموذج وبصمة النص. لا تُنشر هذه الجداول في GitHub.

النسخة العامة لهذا الكتاب تحتاج coverage.complete و1816 معرف صفحة مصدر وsource_ids الصحيحين وidentity_review.verified مع evidence غير فارغ، إضافة إلى الحقوق والمراجعة العلمية ونجاح تقييم النمط الدلالي/الهجين. هذه بوابات إدارية وليست برهانًا علميًا آليًا.
